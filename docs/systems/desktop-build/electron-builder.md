# [Electron Builder](https://www.electron.build/)

Electron Builder is a tool that builds and packages your Electron app for distribution.

## Why did we choose this?

- Electron Builder includes an easy to use auto-update feature, the `electron-updater` package.
- Electron Builder packages the app for distribution, on all OSes and various installers per OS, with a single command `electron-builder`.
- Electron Builder publishes the app to GitHub releases.
- Electron Builder does code signing for Windows and macOS, and notarization for macOS.

## How does it work?

1. `electron-vite` builds the HTML, CSS and JS bundles
2. `electron-builder --[os] --config` packages the app for distribution.

Release types:
- `electron-builder --[os] --config` does not publish to GitHub Releases.
- `electron-builder --[os] --config --publish always` publishes as `latest` on GitHub Releases.
- `electron-builder --[os] --config --publish always -c.publish.releaseType=prerelease` publishes as `prerelease` on GitHub Releases.

## Auto-update

1. `electron-builder --[os] --config --publish always` builds the app for distribution.
2. The `[channel]-[os]-[arch].yml` is generated after the app is built containing update information. The `channel` in our case is the brand name and it is set in the `publish.channel` field in `electron-builder.yml`. The `channel` can be any name but changing it may break the next update because the `channel` will not match the one the user has downloaded.
3. The build and update files are uploaded to GitHub Releases.
4. `electron-updater` checks the repository's GitHub Releases.
5. `electron-updater` looks for the latest release.
6. Under the latest release, it looks for the `[channel]-[os]-[arch].yml` file. The `.yml` file is generated by `electron-builder` not by `electron-updater`.
7. `electron-updater` downloads the file specified in the `.yml` file.

See [Auto-update](https://www.electron.build/docs/features/auto-update) in the Electron Builder documentation.

## Native Node Modules

### How it works?

1. `electron-builder` rebuilds native node modules for the target platform with the architecture of the build machine.
2. Runs [`@electron/rebuild`](https://github.com/electron/rebuild) which scans the `node_modules` directory for native node modules.
3. Runs Electron's version of [`node-gyp`](https://github.com/nodejs/node-gyp) which recompiles the native part of the package for the compatibility with Electron's runtime and the target platform. A `.node` file what is compiled by `node-gyp`.

### Packages that use Native Node Modules

- [`better-sqlite3`](https://github.com/WiseLibs/better-sqlite3)
- [`bufferutil`](https://github.com/websockets/bufferutil)
- [`utf-8-validate`](https://github.com/websockets/utf-8-validate)

### Why does it need to happen?

#### Linux and Windows

For Linux and Windows, the Native Node Modules are prebuilt and are downloaded during `yarn install`. It does not need to be rebuilt because we only build for one architecture on our CI workflow.

#### macOS

For macOS, the Native Node Modules are prebuilt and are downloaded during `yarn install`. The Node Native Modules work during development because the Native Node Module for architecture of the development machine is downloaded. However, during production builds, we build for `universal` (x64 + arm64) and including only the architecture of the development machine would cause issues for the other architecture.

The `npmRebuild` field in the `electron-builder.yml` is set to `true` to rebuild the prebuilt node native modules for x64 and arm64 for macOS. In the future, if we no longer build for `universal` on macOS, we can set `npmRebuild` to `false`.

See [Native Node Modules](https://www.electron.build/docs/features/native-node-modules) in the Electron.js documentation.

## Dependencies

### Electron

Electron provides the runtime environment for the app. Electron Builder packages the HTML, CSS and JS bundles to run in the Electron runtime.
